# ontologies: правила создания онтологии

Лексемы языка — только для кода LLMC. Онтологии — только для компилятора и LLM: программист их в коде не использует.

| Онтология | Файл | Для чего |
|---|---|---|
| языка LLMC | `llmc.json` | смысл каждой лексемы `config/tokens.def`; пояснения `[llmc]` в IR |
| целевого языка | `<язык>/base.json` | перевод лексем в целевой язык, шаблоны объявлений, правила для LLM |
| библиотек целевого языка | `<язык>/<имя>.json` | пакеты и правила для LLM; сверка импортов |

Имя папки — целевой язык из команды `./llmc <проект> <язык>`. Настройки языка — в `targets.<язык>` файла `config/compiler.json`.

## llmc.json

| Раздел | Содержание |
|---|---|
| `about` | описание |
| `keywords` | все слова `%keyword`: `{ "about": "смысл" }` |
| `operators` | все слова `%operator`: `{ "about": "смысл" }` |

```json
"keywords": {
  "virtual": { "about": "перед import, переменной, функцией, методом, class или interface: эту сущность создаёт LLM" }
}
```

## base.json

| Раздел | Содержание |
|---|---|
| `about`, `language` | описание и имя целевого языка, равное имени папки |
| `extensions` | расширения файлов целевого языка; первое — для результата |
| `scripts` | скрипты проекта: `build`, `start`, `test` |
| `packages` | зависимости, нужные всегда или встроенные |
| `comments` | запись комментариев целевого языка: `line`, `open`, `close`, `quotes` — по ней комментарии удаляются из готового кода |
| `keywords` | все слова `%keyword` и только они |
| `operators` | все слова `%operator` и только они |
| `templates` | шаблоны объявлений целевого языка: по ним компилятор переводит код без LLM |
| `rules` | правила для LLM, массив строк |

Запись лексемы:

| Поле | Содержание |
|---|---|
| `about` | смысл и перевод |
| `emit` | перевод: текст или шаблон; `{0}`, `{1}` — части выражения или параметры типа |
| `cast`, `cast:<тип>` | перевод приведения `(тип) x`; `cast:date` — когда `x` имеет тип `date` |
| `integer`, `basic`, `array` | перевод целочисленного деления, проверки простого типа, создания массива |
| `verify` | регулярное выражение, которое должно найтись в коде от LLM; `{name}` — имя объявления |

```json
"keywords": {
  "string": { "about": "строка → string", "emit": "string", "cast": "String({0})", "cast:date": "{0}.toISOString()" }
},
"operators": {
  "==": { "about": "равенство → ===", "emit": "===" },
  "/": { "about": "деление", "emit": "/", "integer": "Math.trunc({0} / {1})" }
}
```

Шаблон в `templates` — строка с местами `{имя}`: `"function": "{export}{async}function {name}({params}): {type} {body}"`.

## Онтология библиотеки

| Раздел | Содержание |
|---|---|
| `about`, `language` | описание и имя целевого языка |
| `mentions` | слова в нижнем регистре; если слово есть в именах или комментариях файла и его интерфейсов-ролей, онтология подключается к запросу LLM |
| `packages` | пакеты библиотеки |
| `rules` | правила для LLM: как оформлять роли и пользоваться библиотекой |

```json
{
  "about": "TypeORM: записи и таблицы PostgreSQL",
  "language": "typescript",
  "mentions": ["typeorm", "таблиц", "сущност"],
  "packages": { "typeorm": { "version": "^1.1.2", "about": "TypeORM", "requires": ["pg"] } },
  "rules": ["Сущность базы данных — запись таблицы → @Entity('таблица') из typeorm"]
}
```

## packages

| Поле | Содержание |
|---|---|
| `version` | версия пакета |
| `url` | адрес для скачивания |
| `path` | локальный путь |
| `about` | назначение пакета и как его импортировать |
| `builtin` | `true` — встроенный пакет, не устанавливается |
| `always` | `true` — ставится в каждый проект |
| `requires` | пакеты, которые ставятся вместе с этим |

В список зависимостей проекта попадают пакеты, которые импортирует готовый код, их `requires` и пакеты с `always`.

## Как онтология заземляет LLM

| Шаг | Действие |
|---|---|
| 1 | IR: код LLMC со всеми комментариями и пояснениями лексем `[llmc]` из `llmc.json` |
| 2 | компилятор переводит файл в целевой язык по `base.json`; на месте `virtual` — `__virtual__` |
| 3 | в запрос попадают IR, перевод, объявления импортированных файлов, `rules` и `packages` из `base.json` и онтологий, подключённых по словам `mentions` |
| 4 | ответ сверяется: нет `__virtual__`; имена и объявления на месте; тела, написанные человеком, не изменены; созданы все файлы `virtual import` и только они; импорты — только пакеты этих онтологий и файлы из `import` |
| 5 | при ошибке сверки LLM получает список ошибок и отвечает заново, до 3 раз |
| 6 | из принятого кода удаляются комментарии; сборка и тесты — на этапе 7 |

## Проверки компилятора

| Проверка | Ошибка |
|---|---|
| каждая лексема `tokens.def` есть в `llmc.json` и `base.json` | `в разделе keywords нет лексем из tokens.def` |
| в `keywords` и `operators` только лексемы `tokens.def` | `онтология описывает только лексемы языка` |
| у каждого оператора есть `emit` | `нет перевода emit` |

## Новый целевой язык

| Шаг | Действие |
|---|---|
| 1 | создать папку `<язык>` и `base.json` со всеми разделами |
| 2 | описать в `keywords` и `operators` все слова из `config/tokens.def` с переводом `emit` |
| 3 | заполнить `templates`, `comments`, `scripts`, `rules` |
| 4 | добавить онтологии библиотек: `mentions`, `packages`, `rules` |
| 5 | добавить `targets.<язык>` в `config/compiler.json`: `manifest`, `install`, `script`, `output` |
| 6 | проверить: `./llmc example <язык> --no-llm` |

## Важно

- Операторы управления и выражения переводятся в синтаксисе C; для целевого языка с другим синтаксисом нужна доработка `src/emit`.
- Оформление ролей (декораторы библиотек) проверяют только сборка и тесты: сверка по имени класса убрана вместе с типами имён.
